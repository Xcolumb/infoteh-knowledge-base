### `server.js` (1332 → 52 строки)

Полностью заменён на точку входа:

- загрузка конфигурации, открытие БД с миграциями;

## 4. Удалено

| Что | Причина |
| --- | --- |
| `app.use('/uploads', express.static(...))` | критическая уязвимость (файлы без авторизации) |
| Дублирование DDL в `server.js`, `seed.js`, `migrate-pto.js` | рассинхронизация схемы |
| Дублирование справочников на клиенте | единый источник в `lib/constants.js` и `/api/pto/meta` |
| Роль «Старший монтажник» для удаления статей через API | расхождение с интерфейсом (теперь только администратор) |
| Общий `cors()` для всех источников | заменён на allowlist `TRUSTED_ORIGINS` |

## 6. Обратная совместимость

- Существующие таблицы и данные не удалялись и не переименовывались.
- Новые поля добавляются через `ALTER TABLE ... ADD COLUMN` с проверкой наличия.
- Для документов ПТО с уже загруженными файлами автоматически создаются записи редакций (`006-backfill-access-demo-and-revisions`).
- Доступ к объектам для действующих сотрудников мигрирован как «все объекты» — поведение не изменилось, права можно сузить в интерфейсе.
- Демо-учётные записи (`ADM002`, `SM002`, `M002`, `PTO01`) помечены как демонстрационные и блокируются в production (`ALLOW_DEMO_ACCOUNTS=0`).
