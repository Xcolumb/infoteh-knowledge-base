# FILE_HANDLING_AND_PREVIEW_REPORT — кириллица в именах файлов и встроенный просмотр

**Дата:** 19.11.2026.
**Ветка:** `feature/pto-modernization`.
**Проверено:** Node.js v26.13.0, автотесты `npm test` — **88/88**, UI-проверки (headless Chromium) — 9/9 по просмотру и брендингу + 13/13 регрессия.

## 1. Причина искажения кириллицы (диагностика)

Цепочка: браузер → `FormData` → `multipart/form-data` → Multer/Busboy → `originalname` → сервер → SQLite → JSON → интерфейс → `Content-Disposition`.

Диагностический эксперимент (загрузка файла `Исполнительная документация по электроснабжению здания.docx` через `multipart/form-data`) показал, что **браузер отправляет имя в UTF-8 корректно**, но библиотека разбора multipart (Busboy, используемая Multer) декодирует байты `filename` как **Latin-1**. В результате в серверном коде `file.originalname` содержит строку из символов `U+00D0, U+0098, U+00D1…` — то есть `Ð˜ÑÐ¿Ð¾Ð»Ð½Ð¸Ñ‚ÐµÐ»ÑŒÐ½Ð°Ñ…`. Именно эта строка сохранялась в БД и отдавалась в интерфейс.

Точка повреждения — **декодирование параметров multipart на сервере**, а не браузер, SQLite или `Content-Disposition`.

После исправления (см. ниже) имя сохраняется в SQLite как `Исполнительная документация по электроснабжению здания.docx`, возвращается в API без изменений и корректно передаётся при скачивании.

## 2. Что исправлено

### 2.1. Восстановление имени при приёме файла

`lib/validate.js` — функция `decodeUploadFileName(raw)`:

- ASCII-имена не меняются;
- имена, где кириллица уже корректна, не меняются;
- если строка содержит типичные артефакты Latin-1 (`Ð`, `Ñ`, диапазон U+00C0–U+00FF) и перекодировка `latin1 → utf8` даёт валидную строку без `U+FFFD`, имя восстанавливается;
- при неоднозначности (символы замены, уже корректный UTF-8, диакритика латиницы) имя остаётся как есть — вслепую перекодировка не выполняется.

Функция применена в `safeOriginalName()` и в фильтре/именовании загружаемых файлов (`lib/files.js`), поэтому исправление действует и для новых загрузок, и для валидации типов.

### 2.2. Разделение имени и хранения

| Что | Как хранится |
| --- | --- |
| `original_name` | в БД (`Оригинальное_имя`), кириллица в UTF-8, до 255 символов |
| `storage_name` | случайное имя `${Date.now()}_${16 hex}${ext}` — не зависит от имени пользователя |
| `storage_path` | `uploads/<storage_name>` |
| `mime_type` | по расширению из белого списка (`MIME_BY_EXTENSION`) |
| `extension` | из восстановленного оригинального имени |

Физические файлы никогда не переименовываются при исправлении БД.

### 2.3. HTTP-заголовки скачивания

`lib/files.js:contentDisposition`:

- `filename="..."` — ASCII-подстановка для старых клиентов;
- `filename*=UTF-8''<percent-encoded>` — RFC 5987 (дополнительно экранируются `'`, `(`, `)`, `*`);
- `inline` разрешён **только** для PDF и изображений; DOCX/XLSX и другие офисные форматы принудительно `attachment`;
- добавлены `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`;
- корректный `Content-Type` из белого списка.

### 2.4. Старые файлы (dry-run и применение)

Скрипт `scripts/report-old-filenames.js` (`npm run report-filenames`) ищет искажённые имена в таблицах `Документ_ПТО`, `Редакция_ПТО`, `Статья`, `Вложение_замечания` и формирует CSV-отчёт `reports/filename-repair-dry-run.csv`:

- таблица, ID, текущее имя, физический файл, предполагаемое имя, восстановимость, основание.

На текущей базе найдено **2 записи** (документ ID 24 и его редакция ID 1): `Ð‘Ð¸Ð·Ð½ÐµÑ-Ð¾Ð±Ð¾ÑÐ½Ð¾Ð²Ð°Ð½Ð¸Ðµ…docx` → `Бизнес-обоснование_пилотной_системы_ПТО.docx`. Восстановление однозначное, поэтому выполнено `--apply` **только для полей БД**; физический файл `uploads/1795062067581_51b55260df6986c7.docx` не тронут. Повторный dry-run показывает 0 искажённых имён.

Флаг `--apply` не запускается автоматически: порядок — сначала dry-run, затем решение владельца данных.

## 3. Встроенный просмотр документов

### 3.1. Разделение «Просмотреть» и «Скачать»

| Действие | Что делает |
| --- | --- |
| **Просмотреть** | открывает модальное окно внутри приложения; файл не скачивается |
| **Скачать оригинал** | отдаёт файл с `Content-Disposition: attachment`, исходное имя сохраняется |

Кнопки есть в карточке документа, у каждой редакции и у вложений замечаний. Для каждой редакции просмотр отдельный; у неактуальной редакции выводится пометка «не актуальная редакция».

### 3.2. Форматы и реализация

| Формат | Режим | Как реализовано |
| --- | --- | --- |
| PDF | `iframe` (inline) | встроенный PDF-просмотрщик браузера: страницы, масштаб, прокрутка, полноэкранный режим; кнопка скачивания отдельно |
| DOCX | `html` | собственный преобразователь `word/document.xml` → безопасный HTML: заголовки, абзацы, жирный/курсив/подчёркивание, списки, таблицы, изображения (data-URI) |
| XLSX | `table` | собственный парсер: список листов, переключение, строки/столбцы, текст и числа; формулы не вычисляются (только сохранённое значение) |
| CSV | `table` | разбор RFC 4180, таблица, ограничение 500 строк × 40 столбцов |
| TXT / MD | `text` | экранированный `<pre>`, без интерпретации как HTML |
| PNG / JPEG | `image` | `<img>` с inline-отдачей через защищённый endpoint |
| DOC / XLS (старые) | `converted` | локальная конвертация в PDF через LibreOffice headless (если установлен); иначе режим `unsupported` с понятным сообщением и кнопкой скачивания |
| Прочее | `unsupported` | сообщение «Скачайте файл для открытия в соответствующей программе» |

### 3.3. Безопасность просмотра

- проверяется сессия и доступ к объекту документа/редакции/замечания (401/403);
- прямой URL не обходит права; ID подменить нельзя — проверка на сервере;
- HTML DOCX генерируется только из белого списка тегов, весь текст экранируется; скрипты и макросы не исполняются (XSS-тест в автотестах);
- ограничения: DOCX ≤ 8 МБ XML, HTML ≤ 2 МБ, изображения ≤ 2 МБ каждое, XLSX ≤ 25 листов × 500 строк × 40 столбцов, ячейка ≤ 500 символов;
- конвертация DOC/XLS: тайм-аут 30 с, результат ≤ 40 МБ, временный каталог в `os.tmpdir()` удаляется после ответа, прямой доступ к нему невозможен;
- просмотр фиксируется в журнале аудита (`Просмотр документа`, `Просмотр редакции`, `Просмотр вложения замечания`);
- внешние сервисы и публичные CDN не используются.

### 3.4. Ограничения

- PDF отображается встроенным движком браузера (собственный интерфейс PDF.js не внедрялся; PDF.js не требуется устанавливать);
- сложное форматирование DOCX (сноски, формулы, OLE-объекты, колонтитулы) не отображается — выводится предупреждение;
- формулы XLSX не вычисляются, показываются сохранённые значения; сводные таблицы/диаграммы не отображаются;
- старые DOC/XLS требуют установленного LibreOffice на сервере (см. `DEPLOYMENT_RU_VPS.md`); в тестовой среде LibreOffice отсутствует, поэтому режим `unsupported` — ожидаемое поведение и проверено тестом;
- большие документы отображаются частично с предупреждением.
