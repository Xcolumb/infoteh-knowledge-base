# PROJECT_STATUS — итоговая оценка готовности

**Проект:** «База знаний и реестр ПТО» ООО «ИНФОТЕХ БАЛАКОВО» → ООО «СтройМонтажГрупп».
**Версия:** 2.0.0 (ветка `feature/pto-modernization`).
**Дата оценки:** 18.11.2026.
**Проверено на:** Node.js v26.13.0, Windows 10 (dev), Chromium; автоматические тесты — 61/61.

---

## 1. Главный вывод

Система **пригодна к пилотной эксплуатации на одном объекте для 3–5 пользователей** — при выполнении обязательных условий раздела 4 (HTTPS, реальные учётные записи, резервное копирование, регламент доступа).
Система **не готова к промышленной эксплуатации без ограничений** и **не является заменой** юридически значимого документооборота: нет ЭЦП, OCR, e-mail-уведомлений, XLSX-выгрузок, ИИ-функций; аудит действий доступен только через API.

## 3. Что проверено и подтверждено

- 61 автоматический тест (аутентификация, права, файлы, изоляция объектов, реестр, статусы, редакции, импорт, комплектность, замечания, поиск, миграции, бэкап/восстановление) — **все пройдены**.
- 33 API-проверки «сквозных» сценариев — все пройдены.
- 13 проверок интерфейса в headless-браузере (панель, документы, карточка, формы, новые разделы, мобильный вид) — все пройдены, ошибок в консоли нет.
- Резервное копирование реальной базы: копия создана, проверена (`integrity: ok`), восстановление в отдельный каталог дало те же данные (10 документов, 22 записи истории, 3 объекта, 4 файла).
- Production-конфигурация без `SESSION_SECRET` не запускается — проверено.
- Существующие данные не изменены по смыслу: демо-документы на месте, тестовые записи удалены.

Полные результаты — `TEST_REPORT.md`, `SECURITY_REPORT.md`.

## 4. Обязательные условия перед реальным запуском

| # | Условие | Ответственный |
| --- | --- | --- |
| 1 | Развернуть VPS по `DEPLOYMENT_RU_VPS.md` (Node, `.env`, systemd, Nginx, сертификат) | Администратор |
| 2 | `ALLOW_DEMO_ACCOUNTS=0`, создать реальных пользователей, сменить демо-пароли | Администратор |
| 3 | Настроить ежедневный бэкап и проверить восстановление на стенде | Администратор |
| 4 | Утвердить регламент доступа и обработки персональных данных | Руководство |
| 5 | Провести приёмочные проверки из `TEST_REPORT.md` на реальном контуре | Заказчик + ИТ |
| 6 | Назначить ответственного за наполнение и актуальность документов | Руководство ПТО |
| 7 | Согласовать формы реестров/отчётов с заказчиком (для этапа 2) | ПТО |

---

## 5. Что требуется от руководства и заказчика

1. Численность и роли пользователей; перечень объектов пилота.
2. Формы ИД и реестров, требования к комплектности (влияет на отчёты и чек-листы).
3. Политика хранения и доступа к персональным данным и документации.
4. Требования к юридической значимости (ЭЦП) и согласованию.
5. Бюджет на этапы 2–4 (см. `ROADMAP.md`).
6. Решение о допустимости внешних ИИ-провайдеров (или локальной модели).
7. Требования к инфраструктуре (корпоративный сервер или облако в РФ, домен, мониторинг).

## 6. Работы, требующие отдельного бюджета

| Работа | Почему отдельно |
| --- | --- |
| OCR сканированных документов | Требует OCR-движка и ресурсов (этап 4) |
| XLSX/печатные формы отчётов | Требует согласования форм заказчика |
| ЭЦП и согласование | Отдельный юридически значимый контур |
| Интеграция с 1С/сметой | Зависит от учётной системы организации |
| ИИ (поиск, извлечение, письма) | Стоимость API/модели + правовая оценка |
| PostgreSQL и горизонтальное масштабирование | При росте числа объектов и пользователей |
| Мониторинг/SIEM | Эксплуатационные расходы |

## 7. Известные недостатки (остались осознанно)

| Недостаток | Влияние | План |
| --- | --- | --- |
| XLSX-выгрузка не реализована | CSV открывается в Excel, но не все формы автоматизированы | ROADMAP, этап 2 |
| OCR не реализован | Сканы не индексируются (честно помечаются «Требует OCR») | этап 4 |
| E-mail/мессенджеры не реализованы | Уведомления только в системе | этап 3 |
| Аудит только через API | Нет экрана журнала для администратора | этап 2 |
| CSP с `unsafe-inline` | Ослабляет защиту от XSS | убрать inline-обработчики |
| Нет антивирусной проверки | Риск вредоносных файлов | ClamAV/шлюз |
| Нет 2FA | Риск компрометации пароля | при внешнем доступе |
| Импорт только CSV | Excel-файлы нужно сохранить в CSV | этап 2 |
| SQLite | Ограничение при росте нагрузки | PostgreSQL при необходимости |

## 8. Оценка рисков дальнейшей эксплуатации

| Риск | Вероятность | Влияние | Снижение |
| --- | --- | --- | --- |
| Ошибки при ручном наполнении | Средняя | Среднее | Инструкция, обучение, контроль |
| Утечка через учётную запись | Средняя | Высокое | Пароли, блокировка, 2FA, аудит |
| Потеря данных | Низкая (при бэкапах) | Критическое | Ежедневные копии, проверка восстановления |
| Несоответствие форм заказчика | Высокая | Высокое | Собрать требования до этапа 2 |
| Правовые вопросы ПДн | Средняя | Высокое | Регламент, основания обработки |
| Смена версии Node ломает сервис | Низкая | Среднее | Фиксация версии, `npm rebuild`, CI |
| Один разработчик | Высокая | Среднее | Документация, тесты, передача знаний |
