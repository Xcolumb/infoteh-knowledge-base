## 2. Автоматизированные тесты по файлам

### `tests/auth.test.js` — аутентификация и права (14 проверок)

- анонимный запрос → 401;
- неверный пароль → 401;
- успешный вход: CSRF-токен, роль, набор прав;
- восстановление сессии по cookie;
- изменяющий запрос без CSRF → 403;
- смена пароля: неверный текущий → 403, слабый новый → 400, успешная смена + вход только с новым паролем;
- выход завершает сессию (последующий запрос → 401);
- блокировка подбора: 6 попыток → 429;
- монтажник не создаёт объекты (403);
- старший монтажник не управляет документами ПТО (`canManage: false`).

### `tests/access.test.js` — доступ к файлам и объектам (12 проверок)

- создание документа с файлом, редакция № 1;
- файл доступен владельцу прав (200, содержимое совпадает);
- анонимный запрос файла → 401;
- инженер без доступа к объекту: документ и файл → 403;
- список документов фильтруется по доступным объектам;
- `/uploads/*` → 404;
- path traversal (`uploads/../../secret.txt`) → 404;
- загрузка `virus.html` → 400;
- замена файла: версия 2, две редакции, старый файл остаётся на диске;
- редакция чужого объекта → 403;
- администратор видит документы всех объектов.

### `tests/pto.test.js` — реестр ПТО (7 проверок)

- создание документа;
- смена статуса фиксируется в истории (было/стало, комментарий);
- повторная смена на тот же статус → 400;
- CSV-реестр содержит документ, начинается с BOM;
- импорт с ошибкой отменяется целиком (частичной записи нет);
- корректный импорт создаёт 2 документа;
- экспорт только для авторизованных (401).

### `tests/completeness-remarks.test.js` — комплектность и замечания (12 проверок)

- создание комплекта и требования;
- позиция без документа — «Отсутствует»;
- привязка документа меняет состояние;
- документ другого объекта привязать нельзя (409);
- отчёт о недостающих позициях (CSV);
- создание замечания с автономером `ЗМ-ГГГГ-NNN`;
- уведомление ответственному;
- смена статуса, комментарий, история;
- фильтр «просроченные»;
- ручной пересчёт уведомлений.

### `tests/search.test.js` — поиск (5 проверок)

- статус движка (`fts5`);
- поиск по названию;
- пользователь без доступа к объекту не находит документ;
- короткий запрос не выполняется;
- индекс обновляется после переименования.

### `tests/migrations.test.js` — миграции (3 проверки)

- миграции добавляют таблицы и поля к «старой» БД;
- повторный запуск безопасен (число миграций не растёт);

### `tests/backup.test.js` — резервное копирование (4 проверки)

## 5. Что не тестировалось (и почему)

| Проверка | Причина |
| --- | --- |
| Нагрузочное тестирование (50+ пользователей, объём файлов) | Нет утверждённых требований и тестовой инфраструктуры; для пилота 3–5 пользователей оценка достаточна |
| Тестирование на проникновение | Вне объёма задания; требуется отдельный специалист |
| E-mail и мессенджеры | Функция не реализована (заложена как расширение) |
| XLSX-выгрузка | Не реализована |
| OCR сканированных документов | Не реализован; система честно помечает «требует OCR» |
| ИИ-функции | Провайдер отключён; проверена только заглушка (501) и статус |
| Совместимость со всеми браузерами | Проверено в Chromium; целевые — актуальные Chrome/Edge/Yandex/Firefox |
| Работа под нагрузкой при параллельной записи | Не проверялась |

## 6. Как повторить проверки

```bash
# автотесты (изолированные временные БД)
npm test

# резервная копия и проверка
npm run backup

# восстановление (осторожно: перезаписывает рабочие данные, требуется --force)
npm run restore -- backups/backup-XXXX --force

# миграции
npm run migrate
```

Для ручной проверки интерфейса: `npm start`, затем `http://127.0.0.1:3001`.
